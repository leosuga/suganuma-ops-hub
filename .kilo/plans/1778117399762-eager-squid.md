15. **Docker socket do Coolify estava faltando**: O container `coolify` foi inicializado sem `/var/run/docker.sock` montado (instalação incompleta). Corrigido via `docker-compose.custom.yml` com `bind mount read_only`.
16. **Coolify usa proxy Traefik por padrão**: Conflita com Caddy nas portas 80/443. Não é possível usar Coolify para deploy sem migrar o proxy do VPS.
17. **Sanctum tokens usam SHA-256, não bcrypt**: API do Coolify requer `Authorization: Bearer {id}|{plaintext}`. O campo `token` no banco é `hash('sha256', plaintext)`. Para criar token via SQL: gerar plaintext com `secrets.token_hex(32)`, inserir `hashlib.sha256(plaintext).hexdigest()`.
18. **Caddyfile completo no VPS**: Serve WordPress (OpenLiteSpeed), n8n, Supabase (Studio + API), Qdrant, Authentik, Coolify, Nextcloud/Immich via Tailscale, e Ops Hub.
19. **Deploy manual é confiável**: Build ~8 min, zero downtime, DNS interno do Docker resolve container novo sem IP fixo. Pipeline funciona — não há ganho urgente para trocar.

## Aprendizados críticos da sessão 2026-05-09

1. **Docker DNS interno > IP fixo**: O erro 502 após deploy foi causado pelo Caddy apontando para IP fixo do container antigo. `--hostname` + `reverse_proxy hostname:3000` resolve via DNS do Docker e elimina o problema.
2. **`typedRoutes` não é viável com BottomNav**: O `BottomNav.tsx` usa `string` em vez de literais para hrefs. Habilitar `typedRoutes` quebra o build instantaneamente.
3. **`@tailwindcss/typography` v0.5.19 é incompatível com Tailwind v4**: Não basta instalar. O plugin `@plugin "@tailwindcss/typography"` no CSS falha com `Cannot find module 'tailwindcss/dist/plugin.js'`. **Solução**: usar a tag `next` (`0.5.0-alpha.3`) que é compatível com v4. Build + tests passam.
4. **Gerar PNGs de ícones PWA via Pillow**: Não há conversores SVG→PNG nativos no macOS (Inkscape, rsvg-convert). Pillow (Python) funciona bem — `Image.new`, `ImageDraw.Draw`, `ImageFont.truetype`, `rounded_rectangle` para reproduzir o design SVG (fundo #121212, cantos arredondados, texto Omega #55D7ED).
5. **`@next/bundle-analyzer` é incompatível com Turbopack**: O analyzer clássico não gera relatório em builds com Turbopack. `next experimental-analyze` não produziu output útil no tempo disponível.
6. **ESLint rules `react-hooks/set-state-in-effect` e `react-hooks/refs` geram falsos positivos**: Patterns comuns como `useEffect(() => setMounted(true), [])` e `queryKeyRef.current = queryKey` são sinalizados como errors. Desativar essas rules é seguro para este projeto.
7. **Deploy com Node 22 funciona**: Build no VPS com `node:22-alpine` passou sem erros. A imagem está em produção agora.
8. **Existem 9 migrations, não 10**: `0001` a `0009`. O plano mencionava 10 erroneamente.
9. **React Compiler no Next.js 16**: `reactCompiler: true` funciona (não `experimental.reactCompiler`). Requer `babel-plugin-react-compiler` instalado como `devDependency`. Build + tests passam sem alterações de código.
10. **Supabase CLI `--linked` só funciona para projetos Cloud**: Nosso Supabase é self-hosted (`api.suganuma.com.br`), não um projeto da Supabase Cloud. `--local` requer Docker daemon. Tipos manuais validados via audit são suficientes.
11. **`queryOptions` do TanStack v5 centraliza `queryKey` + `queryFn`**: Exportar `tasksOptions`, `accountsOptions`, etc. melhora DX e permite `queryClient.prefetchQuery()` server-side no futuro.
12. **Remover `@serwist/next` e `lucide-react` foi seguro**: Ambos não tinham imports em `src/`. `@serwist/next` era lixo (SW é manual), `lucide-react` foi completamente substituído por SVG inline.
13. **React 19.2.4 → 19.2.6 é patch in-place**: `package.json` + `npm install`, nenhuma alteração de código. Build + tests passam imediatamente.
